\section{Алгоритм DDA}

Одним із базових алгоритмів проходження дискретного простору вздовж променя є алгоритм цифрового диференціального аналізатора \engl{Digital Differential Analyzer, DDA}. Спочатку він застосовувався для растеризації ліній на двовимірній сітці, однак згодом був узагальнений на тривимірний випадок і може використовуватися для проходження регулярних воксельних сіток.

У контексті трасування променів у воксельному просторі алгоритм DDA дозволяє ітеруватися вздовж променя з фіксованим кроком, обчислюючи на кожному кроці координати точки на промені та визначаючи відповідний воксель. Таким чином, промінь відстежується послідовно, крок за кроком, а складність алгоритму пропорційна довжині променя та обраному кроку, а не безпосередньо кількості відвіданих вокселів.

Формально, промінь у тривимірному просторі задається параметричним рівнянням:
\begin{equation*}
\mathbf{r}(t) = \mathbf{o} + t \cdot \mathbf{d},
\end{equation*}
де $\mathbf{o}$ — точка початку променя, $\mathbf{d}$ — нормалізований вектор напрямку, а $t \ge 0$ — параметр.

Метою алгоритму DDA є визначення послідовності цілих координат $(x, y, z)$ вокселів, через які проходить промінь, шляхом ітеративного крокування \linebreak вздовж променя і взяття цілих координат відповідно до обчисленої позиції.

    \label{fig:dda_2d}

Процес повторюється доти, доки промінь не досягне цільового вокселя або не покине межі воксельного об'єму.

Основною перевагою наївного DDA є його простота реалізації та універсальність. Водночас він є менш ефективним для великих сцен, оскільки виконує багато зайвих обчислень і може пропускати тонкі вокселі або перетинати один воксель декілька разів, якщо крок обраний невдало.

\section{Fast Voxel Traversal Algorithm\\(Amanatides and Woo)}

Алгоритм швидкого проходження воксельного простору, запропонований Эндрю Ву та Джоном Аманатайдс з університету Торонто, є спеціалізованим та оптимізованим варіантом тривимірного DDA, адаптованим саме для задач трасування променів у воксельних сітках.

Його ключовою особливістю є те, що всі величини, необхідні для проходження, обчислюються один раз перед початком ітерацій, а подальші кроки алгоритму не потребують операцій ділення, що є критично важливим для продуктивності на GPU.

\newpage

\begin{figure}[ht!]
    \centering
    \input{figures/a&w.tex}
    \caption\centering{Проходження променя через послідовність вокселів за алгоритмом Amanatides and Woo.}
    \label{fig:amanatides}
\end{figure}

Алгоритм починається з визначення початкового вокселя, у якому знаходиться точка $\mathbf{o}$. Далі для кожної осі $i$ обчислюються:
\begin{align*}
    \mathbf{step}_i    &= \operatorname*{sign}(d_i),\\
    \mathbf{tDelta}_i  &= \frac{s_i}{|d_i|},\\
    \mathbf{tMax}_i    &= \begin{cases}
        (\lfloor o_i \rfloor + 1 - o_i) \cdot \mathbf{tDelta}_i, & d_i > 0 \\
        (o_i - \lfloor o_i \rfloor) \cdot \mathbf{tDelta}_i, & d_i < 0
    \end{cases}
\end{align*}

\begin{enumerate}[itemsep=0pt]
    \item $\mathbf{step}_i$ --- напрям руху по осі ($+1$ або $-1$);
    \item $\mathbf{tDelta}_i$ --- приріст параметра $t$ між двома послідовними межами вокселів по осі $i$, де $s_i$ --- розмір вокселя по осі $i$;
    \item $\mathbf{tMax}_i$ --- значення $t$, при якому промінь уперше перетне межу наступного вокселя вздовж осі $i$.
\end{enumerate}

    Далі виконується основний цикл проходження:
    \begin{itemize}[itemsep=0pt, topsep=0pt]
        \item На кожному кроці вибирається мінімальне з $\mathbf{tMax}_x, \mathbf{tMax}_y, \mathbf{tMax}_z$, що визначає, через яку грань вокселя промінь вийде наступним.
        \item Відповідний індекс координати збільшується або зменшується згідно $\mathbf{step}_i$.
        \item $\mathbf{tMax}_i$ оновлюється: $\mathbf{tMax}_i \leftarrow \mathbf{tMax}_i + \mathbf{tDelta}_i$.
        \item Перевіряється вихід за межі об'єму або досягнення цільового вокселя.
    \end{itemize}

    Псевдокод алгоритму:
    \begin{rustcode}
    loop {
        if t_max_x < t_max_y {
            if t_max_x < t_max_z {
                x += step_x;
                if x == just_out_x {
                    return None; 
                }
                t_max_x += t_delta_x;
            } else {
                z += step_z;
                if z == just_out_z {
                    return None; 
                }
                t_max_z += t_delta_z;
            }
        } else {
            if t_max_y < t_max_z {
                y += step_y;
                if y == just_out_y {
                    return None; 
                }
                t_max_y += t_delta_y;
            } else {
                z += step_z;
                if z == just_out_z {
                    return None; 
                }
                t_max_z += t_delta_z;
            }
        }

        let result = load_voxel(x, y, z);
        if result.is_some() {
            return result;
        }
    }
    \end{rustcode}

\newpage
На кожному кроці вибирається мінімальне з $\mathbf{tMax}_x, \mathbf{tMax}_y, \mathbf{tMax}_z$, що визначає, через яку грань вокселя промінь вийде наступним.

У порівнянні з наївним підходом, алгоритм Amanatides and Woo:
\begin{itemize}[itemsep=0pt, topsep=0pt]
    \item гарантує відвідування кожного вокселя не більше одного разу;
    \item не використовує умовних перевірок перетину з геометрією;
    \item має передбачуваний контроль потоку виконання, що добре підходить для SIMD-архітектури GPU.
\end{itemize}

Завдяки цим властивостям, алгоритм широко використовується для трасування променів у воксельних сценах, особливо на GPU.

Саме цей алгоритм використовується як базовий механізм трасування у подальших розділах роботи.

\section{Структури даних для трасування на GPU}

Ефективність алгоритму трасування променів у воксельному просторі значною мірою залежить не лише від самого алгоритму проходження, а й від обраної структури даних для зберігання сцени. В умовах GPU існують суттєві обмеження, зокрема відсутність вказівників, обмежений стек викликів та висока вартість розгалужень.

\subsection{Лінійна BVH}

\textbf{Ієрархія обмежувальних об'ємів} \engl{Bounding Volume Hierarchy, BVH} — це класична структура даних для прискорення тестів на перетин променя з геометрією сцени. Основна ідея BVH полягає в побудові ієрархічного дерева обмежувальних об'ємів, де кожен вузол містить обмежувальний об'єм для певної групи примітивів сцени (трикутників, полігонів тощо). Листові вузли містять безпосередньо примітиви, а внутрішні вузли — посилання на нащадків, що дозволяє швидко відсіювати великі частини сцени при трасуванні променів.

На GPU класичне дерево з вказівниками використовувати складно через відсутність прямої підтримки динамічних структур і рекурсії у шейдерах. Для вирішення цієї проблеми застосовується \textbf{лінійна BVH} \engl{Linear BVH, LBVH}, де вузли дерева зберігаються у лінійному масиві. Кожен вузол містить:
\begin{itemize}[itemsep=0pt, topsep=0pt]
    \item координати обмежувального об'єму;
    \item індекси лівого та правого нащадків у масиві;
    \item інформацію про листовий вузол (наприклад, індекси примітивів).
\end{itemize}

Цей підхід дозволяє обійтись без рекурсії та працювати з детермінованим доступом до пам'яті, що є критично важливим для продуктивності на GPU. Проте, для задач трасування у воксельному просторі використання LBVH є надлишковим. Основні причини:
\begin{enumerate}[itemsep=0pt, topsep=0pt]
    \item \textbf{Вартість побудови та оновлення.} Навіть лінійна BVH потребує додаткових обчислень для сортування і побудови масиву вузлів. Для динамічних сцен або при зміні розташування об'єктів це може значно вплинути на швидкодію.
    \item \textbf{Пропуск порожніх областей.} LBVH добре працює для полігонів, де більшість простору порожня. У випадку вокселізованої сцени всі активні вокселі вже зберігаються у єдиному об'ємі, і пропускати порожні зони можна більш ефективно через MIP-рівні 3D текстури.
\end{enumerate}

Замість LBVH у цій роботі обрана стратегія використання \textbf{загального світового воксельного об'єму} \engl{World Voxel Volume} з MIP-рівнями, що дозволяє:
\begin{itemize}[itemsep=0pt, topsep=0pt]
    \item зберігати всю сцену в єдиній 3D текстурі;
    \item виконувати швидкий доступ до вокселів за константний час через тривимірний індекс;
    \item реалізувати ефективний пропуск порожніх областей аналогічно до октодерева, без необхідності зберігати явну ієрархію з вузлів і вказівників;
    \item спростити реалізацію трасування на GPU, уникаючи складної рекурсії та великих масивів LBVH.
\end{itemize}

Таким чином, LBVH залишається корисною концепцією для полігональної геометрії, проте у контексті воксельного рендерингу її роль значно зменшується, а структура світового об'єму з MIP-рівнями забезпечує подібні переваги, зберігаючи при цьому простоту та ефективність GPU-реалізації.

\subsection{3D текстура}

Найпростішим і водночас найефективнішим способом зберігання воксельного об'єму на GPU є використання 3D текстури. Кожен тексель відповідає одному вокселю та може містити інформацію про:
\begin{itemize}[itemsep=0pt, topsep=0pt]
    \item твердість вокселя;
    \item колір;
    \item ідентифікатор матеріалу.
\end{itemize}

Перевагою 3D текстур є апаратна підтримка кешування та можливість швидкого довільного доступу за координатами $(x, y, z)$.

\subsection{3D MIP-map як аналог octree}

\textbf{MIP-mapping} --- це техніка текстурування, яка використовує кілька копій однієї й тієї ж текстури з різним рівнем деталізації. MIP-рівні 3D текстури можуть бути використані як спрощений аналог октодерева. Кожен наступний рівень відповідає простору, де кожен воксель агрегує інформацію з $2 \times 2 \times 2$ вокселів попереднього рівня: якщо воксель твердий, то в даному просторі є хоча б 1 твердий воксель на нижчому рівні.

    \label{fig:mip_octree}

Це дозволяє:
\begin{itemize}[itemsep=0pt, topsep=0pt]
    \item швидко перевіряти великі області простору на порожність;
    \item виконувати грубий тест перетину на старших рівнях;
    \item переходити до точнішого рівня лише за необхідності.
\end{itemize}

\subsection{Загальний воксельний об'єм\\(World Volume)}

\section{Оптимізації}

Для досягнення прийнятної продуктивності у реальному часі необхідно застосовувати низку оптимізацій:
\begin{itemize}[itemsep=0pt, topsep=0pt]
    \item використання MIP-рівнів для пропуску порожніх ділянок;
    \item обмеження максимальної кількості кроків DDA;
    \item ранній вихід при досягненні повністю непрозорого вокселя;
    \item зниження точності обчислень там, де це не впливає на візуальну якість.
\end{itemize}

Сукупність наведених методів дозволяє реалізувати ефективний алгоритм трасування променів у воксельному просторі, придатний для використання у інтерактивних графічних застосунках.
